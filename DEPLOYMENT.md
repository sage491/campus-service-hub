# Deployment instructions

Campus Service Hub is deployed as two services:

1. A Node.js backend that connects to MongoDB and serves `/api`.
2. A static frontend generated by Vite.

The backend and frontend may be hosted on the same platform or on separate platforms. The commands and environment variables below apply to either arrangement.

## Vercel configuration

For the Vercel project connected to this repository, use the following settings:

| Setting | Value |
| --- | --- |
| Root Directory | `frontend` |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

The SPA fallback is defined in `frontend/vercel.json`, so direct navigation and refreshes on `/`, `/login`, `/register`, and authenticated routes load the React application.

## CORS configuration

The backend enables CORS in `backend/src/app.js` and allows the origin configured by `CLIENT_URL`. Set `CLIENT_URL` to the exact frontend origin in the backend deployment:

```text
CLIENT_URL=https://portal.example.com
```

Do not include a trailing path such as `/login`, and do not use `*` for a production deployment. If the frontend and backend use different domains, the frontend browser requests will be accepted only after `CLIENT_URL` matches the frontend domain. Restart or redeploy the backend after changing this variable.

## Prerequisites

- Node.js 20 or later
- npm 10 or later
- A MongoDB Atlas cluster
- A production domain for the frontend
- A publicly reachable backend URL if the services are hosted separately

## 1. Prepare MongoDB Atlas

1. Create or select a MongoDB Atlas cluster.
2. Create a database user with access to the application database.
3. Add the deployment provider's outbound IP addresses to the Atlas network access list. For temporary testing only, `0.0.0.0/0` can be used, but a restricted allowlist is recommended for production.
4. Copy the connection string and replace its username, password, and database name as needed.

## 2. Configure the backend

Create these environment variables on the backend service. Do not commit them to the repository.

| Variable | Required | Value |
| --- | --- | --- |
| `PORT` | No | The port supplied by the hosting provider. The application defaults to `5000` when unset. |
| `MONGODB_URI` | Yes | The MongoDB Atlas connection string. |
| `JWT_SECRET` | Yes | A long, random, production-only secret. |
| `JWT_EXPIRES_IN` | No | JWT lifetime, such as `7d`. |
| `CLIENT_URL` | Yes | The exact public frontend origin, including protocol, such as `https://portal.example.com`. |
| `ADMIN_NAME` | No | Name for the initial administrator account. |
| `ADMIN_EMAIL` | No | Email for the initial administrator account. Set together with `ADMIN_PASSWORD`. |
| `ADMIN_PASSWORD` | No | Strong password for the initial administrator account. Set together with `ADMIN_EMAIL`. |

Use the backend directory as the service root:

```powershell
cd backend
npm ci
npm start
```

The production start command is `npm start`, which runs `node src/server.js`. Do not use `npm run dev` in production.

If both `ADMIN_EMAIL` and `ADMIN_PASSWORD` are set, the server creates that administrator once, if the email does not already exist. Remove or clear `ADMIN_PASSWORD` after the first successful deployment if bootstrap credentials are not needed.

## 3. Configure and build the frontend

Set the following environment variable on the frontend build service:

| Variable | Required | Value |
| --- | --- | --- |
| `VITE_API_URL` | Yes when services are separate | The backend origin or API URL, such as `https://api.example.com` or `https://api.example.com/api`. The frontend normalizes either form to the `/api` prefix. |

If the frontend and backend share one origin and the deployment proxy forwards `/api` to the backend, `VITE_API_URL` may be omitted because the client defaults to `/api`.

Use the frontend directory as the build service root:

```powershell
cd frontend
npm ci
npm run build
```

Publish the generated `frontend/dist` directory as the static site. The frontend is a single-page application, so configure the hosting provider to rewrite unknown routes to `index.html`.

`VITE_API_URL` is embedded during the build. Set it before running `npm run build`; changing it after the build has no effect.

## 4. Deploy order

1. Deploy the backend with `MONGODB_URI`, `JWT_SECRET`, and the final frontend origin.
2. Confirm the backend health endpoint responds at `https://<backend-host>/api/health`.
3. Set `VITE_API_URL` to the backend API URL and build/deploy the frontend.
4. Update `CLIENT_URL` if the frontend domain changes, then restart or redeploy the backend.

## 5. Verify the deployment

Check the health endpoint:

```powershell
curl https://<backend-host>/api/health
```

The response should report an available API and a connected database. Then verify in a browser:

1. The frontend loads from its public URL.
2. Registration and login succeed.
3. An authenticated request reaches the backend without a CORS error.
4. Refreshing a nested frontend route still loads the application.
5. An administrator can create or manage the expected campus-service records.

For an API-level check from a checkout with the test dependencies installed:

```powershell
cd backend
npm run test:api
```

## Production security checklist

- Use HTTPS for both services.
- Use a unique random `JWT_SECRET`; never use the placeholder from `.env.example`.
- Do not commit `.env` files or expose backend secrets as frontend variables.
- Restrict MongoDB network access where the hosting provider permits it.
- Set `CLIENT_URL` to one trusted origin rather than `*`.
- Use a strong one-time `ADMIN_PASSWORD`, then remove bootstrap credentials.
- Review application and database logs after the first deployment.

## Common deployment issues

### CORS errors

Set `CLIENT_URL` to the exact frontend origin, including `https://` and excluding any path. Restart the backend after changing it.

### Frontend calls `localhost`

Set `VITE_API_URL` to the deployed backend origin or its `/api` URL, then rebuild the frontend. Vite variables are build-time values. The client sends login requests to `POST <backend-origin>/api/auth/login`.

### Database is disconnected

Verify `MONGODB_URI`, the Atlas database user's credentials, the database name, and the Atlas network access list. Restart the backend after correcting the variable.

### Frontend routes return 404 after refresh

Configure the static host's SPA fallback so routes other than asset paths serve `index.html`.
